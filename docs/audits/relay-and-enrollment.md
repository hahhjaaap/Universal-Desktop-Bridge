## Ownership, grants, and revocation

Account Fleet derives an immutable team/UUID principal from Access identity or a verified assertion. The registry uses a digest of the principal. Every routed call checks membership and re-verifies the device's current token record, owner, request ID, and revocation state before passing one call to the per-device MCP gateway. See `cloudflare/src/account-fleet.js:41–64,174–185,327–345` and `cloudflare/src/index.js:203–218`. The direct device route uses that device's Durable Object, then requires an Access or OAuth grant for that exact device (`cloudflare/src/index.js:107–112`, `cloudflare/src/oauth.js:87–119,135–163`). No cross-owner routing was established through these normal paths.

Browser-enrolled read grants are limited to `bridge_status`, resolved from the immutable owner on each request, and disabled by explicit tenant policy. Revocation marks the device record revoked, removes the token and proof material, and closes its sockets. The resulting enrolled grant should cease once revocation takes effect. Earlier in-flight actions may already have taken effect. Independently configured static grants have their own lifecycle. See `cloudflare/src/setup-service.js:21–29,70–80` and `cloudflare/src/index.js:300–319`. Simultaneous reconnect and revocation timing was not verified on hosted Durable Objects.

## Pairing, transport, and diagnostics

Administrator-issued pairing uses a random 32-byte code, a stored digest, a ten-minute TTL and a transactional five-failure cap. Successful use consumes the grant. See `cloudflare/src/pairing.js:3–15` and `cloudflare/src/index.js:68–93,275–298`. Relay replies must match a pending ID, socket and original RPC ID. Each accepted reply consumes that reservation. Timeout and send/disconnect failures are marked uncertain. This correlates replies, while replay of separate user requests is governed by the caller and tool semantics. See `cloudflare/src/index.js:356–430` and `src/udb/cloud_agent.py:182–267,488–505,522–566`.

Request JSON is bounded to 256 KiB (`cloudflare/src/auth.js:34–64`). Relay frames are bounded to one MiB on both sides (`cloudflare/src/index.js:35,390–415`, `src/udb/cloud_agent.py:37,109–135,584–605`). The account and device MCP routes reject cross-origin browser calls (`cloudflare/src/account-fleet.js:274–280`, `cloudflare/src/mcp.js:216–223`). Error bodies for authentication and relay transport are fixed categories. The reviewed relay and agent connection logs emit categories, counts and elapsed times. They do not print credentials or local paths in these branches. Scope does not extend to tool results, child stderr or platform-access logs. See `cloudflare/src/mcp.js:25–30,191–213,244–258` and `src/udb/cloud_agent.py:571–580,635–646`.

`UDB_ENABLE_LOCAL_TOOL_SYNC` exposes `ENROLLED_CATALOG` to enrolled owners when the original grant is only `bridge_status`. Discovery lists the catalog, while dispatch for tools outside the original grant requires the relevant relay flag and the fresh Windows permission report. Owner and Companion static grants remain exact per device and subject. Tenant policy disables those optional expansions. Edge discovery filters metadata to allowed read tools. See `cloudflare/src/access.js:270–299`, `cloudflare/src/local-permissions.js:7–45`, `cloudflare/src/owner-tools.js:39–46`, `cloudflare/src/tenant-policy.js:80–92` and `cloudflare/src/edge-discovery.js:56–75`. The agent prewarm path sends a read-only ping, starts one proxy and treats failure as a connection failure (`src/udb/cloud_agent.py:361–381,569–580`).
